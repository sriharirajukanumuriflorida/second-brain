# Name the Pattern Before You Build It

**Diagram which of the five workflow shapes a task matches — Prompt Chaining, Routing, Parallelization, Evaluator-Optimizer, Orchestrator-Workers — before writing code.** A diagram is cheap to revise; a half-built implementation of the wrong pattern is not, and a task that can't be cleanly diagrammed as one of the five is itself a signal it needs further decomposition or genuine agentic control.

> One-liner: pick the pattern on paper first — the question is never which pattern sounds smarter, it's which one matches the task's actual shape.
