# SE Week 01 SOLID Principles Quick Reference

SOLID is a change-management checklist, not an object-oriented purity contest.

- **Single Responsibility**: one module should have one primary reason to change.
- **Open/Closed**: add new variants by extending a seam when variation is frequent.
- **Liskov Substitution**: every implementation of a port should satisfy the same behavioral contract.
- **Interface Segregation**: clients should depend only on capabilities they use.
- **Dependency Inversion**: high-level policy depends on abstractions; infrastructure details plug in from the outside.

> One-liner: **SOLID is about containing blast radius when requirements change** — especially DIP at the boundary between domain policy and infrastructure.
